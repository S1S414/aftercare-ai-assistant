# 售后服务与 AI 辅助工单系统

面向本地模拟场景的 Flask 应用：顾客描述问题，AI 提供分类与描述建议，经顾客核对后创建工单；客服领取、记录处理结果并关闭，顾客可查看结果。

支持本地真实模型体验和免费在线规则模拟两种模式。所有订单与处理均为模拟，不执行支付、退款或补发。

## 免费在线演示部署

仓库提供 Render 免费部署配置：[部署步骤与数据边界](docs/public-demo-deployment.md)。在线模式按访客隔离临时数据，可切换顾客和客服走完流程；模型部分为明确标注的规则模拟，不调用真实 AI，不产生模型费用。服务休眠或重启可能清空临时数据。在线体验：[售后流程演示（规则模拟）](https://s1s414.pythonanywhere.com/)，现运行于PythonAnywhere。

## 已实现功能

| 模块 | 行为 |
|---|---|
| 角色与工单 | 顾客查看本人订单和工单；客服领取、关闭；记录状态变更 |
| 政策查询 | 本地模拟政策检索、带来源的模型回答、资料不足时拒答 |
| AI 整理 | 生成分类和描述建议；采纳、保存、建单由用户分别确认 |
| 调用管理 | 状态、耗时、Token与请求编号；项目共享次数限制，不自动重试 |
| 统计 | 新建工单、当前待处理、关闭时长与建单率，标明各指标口径 |
| 数据维护 | 草稿筛选分页、真实删除、超过7天的草稿归组；本机工具清理旧调用和备份并报告空间变化 |

技术栈：Python、Flask、SQLite、Jinja、原生 JavaScript。政策检索为本地词项检索；模型使用有上限的小语料上下文，不宣称实现向量检索或自主 Agent。

## 本地启动（Windows PowerShell）

进入下载后的项目目录，使用 Python 3.10 创建环境并安装依赖：

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m flask --app app init-db
.\.venv\Scripts\python.exe -m flask --app app seed-demo
```

初始化提示输入至少12字符的演示密码，不显示输入字符。首次生成4个模拟账号，共用本次设置的密码：demo_customer_a、demo_customer_b、demo_staff_a、demo_staff_b。重复初始化不会清空数据，也不会重置既有账号密码。

体验不使用模型的工单流程：

```powershell
.\.venv\Scripts\python.exe app.py
```

如需模型功能，先停止前一个服务，再运行：

```powershell
.\.venv\Scripts\python.exe start_local.py
```

在隐藏提示中输入自己的 DeepSeek API 密钥。启动本身不请求模型；主动点击模型问答或整理按钮时会向平台发送请求，可能产生费用。当前默认模型名为 deepseek-flash，可用性以实际平台响应为准。

浏览器打开 http://127.0.0.1:5005 。服务只监听本机；保留运行窗口，停止时按 Ctrl+C。默认会话密钥在进程重启后变化，可能需要重新登录。无需模型时不要点击付费模型按钮。

## 演示顺序

1. 顾客 demo_customer_a 登录，在订单页进入售后助手，选择 DEMO-002，填写问题并保存草稿。
2. 自己选择问题类型并完善描述，或请求一次 AI 整理、核对建议并填入；保存修改后确认建单。
3. 退出并登录 demo_staff_a，在客服工作台找到本次工单，领取、填写模拟处理结果并关闭。
4. 切回顾客，在我的工单查看相同处理结果。
5. 客服核对售后统计与模型调用记录。统计页可先返回客服工作台进入调用记录。

## 测试与已验证结果

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

工程测试使用临时数据库与模拟模型响应，不等于真实模型质量评估。2026-10-12用户亲自完成模拟工单#6主流程；一次真实整理记录为832 Token、766 ms。这是单次观测，不是准确率或性能承诺。

2026-10-13完整工程回归：122项测试在原环境和全新Python 3.12依赖环境通过。公网主流程由用户完成建单、领取关闭、结果查看及统计核对；详见[演示验收范围](docs/public-demo-acceptance.md)。

## 已知限制

- 已完成本地与公网演示主流程验证，未做生产容量或完整安全审计。公网采用独立演示模式；本机维护工具不对外开放。
- 模型曾出现401；后来独立认证及实际整理恢复，但反复出现的根因未查明。检查工具可安全展示错误摘要，不能保证自动修复认证。
- 调用记录页面仅加载最近100条，筛选不覆盖全部历史。
- 删除数据库记录与数据库文件缩小是不同结果；维护工具报告实际字节变化。独立备份须另行选择删除，备份自动轮换尚未实现。
- 锁定依赖为本地验证基线；公网部署前仍需依赖安全检查及部署设计。
