# 架构与验证边界

浏览器通过Flask页面与JSON接口访问业务服务，SQLite保存用户、订单、工单、事件、草稿与调用记录。顾客权限按账号归属检查；客服通过领取和关闭完成工单处理。

AI整理路径：已保存草稿 → 固定政策上下文 → 官方模型接口 → 结构及引用检查 → 展示建议 → 用户采纳并保存 → 用户确认建单。模型建议不会自动提交工单或执行退款。版本检查、幂等约束与事务用于约束重复请求和状态变化。

政策检索采用本地词项方法。当前小语料模式提供有大小上限的完整政策上下文，并保留来源；不是向量数据库，也不是任意工具自主执行的Agent。

调用台账保存状态、时间、用量和请求编号，不保存问题正文、模型答案和API密钥。次数限制按项目共享，不等于平台金额预算。失败和未知结果仍占次数，不自动重试。

自动测试覆盖身份权限、工单事务、草稿版本、模型结构校验、限额、统计、删除与备份恢复等场景。测试通过不代表无缺陷；模型质量仅有有限开发案例，不能宣称泛化准确率。

当前默认仅监听127.0.0.1。公网部署前仍须完成账号策略、登录限流、依赖与安全审查、部署服务及数据隔离等工作。
